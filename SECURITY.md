# Безпека ServerWatch

## Межі доступу

Вебпанель доступна лише після пароля та TOTP. Хеш пароля — Werkzeug scrypt;
TOTP-секрет зберігається зашифрованим. Первинний QR доступний протягом 5 хвилин
після перевірки пароля й лише до активації TOTP. Один часовий крок TOTP не можна
використати повторно. Після входу сесія очищується, cookie має HttpOnly, SameSite=Lax,
Secure у режимі HTTPS, строк життя — 8 годин. Форми захищені Flask-WTF CSRF.
Невдалі входи обліковуються за логіном та IP у БД: 5 спроб, блокування 15 хвилин.
Скидання TOTP можливе лише через локальну CLI-команду та права Linux-користувача.

Gunicorn слухає Unix socket, доступний Nginx. ProxyFix довіряє одному проксі;
Nginx **перезаписує** X-Forwarded-For і X-Forwarded-Proto. Не виставляйте Gunicorn
на публічний TCP-порт, інакше заголовки можуть підмінити адресу клієнта.

Для сценарію без домену використовується deploy/nginx-tunnel.conf: Nginx слухає
тільки 127.0.0.1:8080, браузер підключається через SSH forwarding на власний loopback.
У цьому режимі SESSION_COOKIE_SECURE=false, бо локальна частина HTTP; мережевий
трафік до VPS шифрується SSH. Не відкривайте 8080 назовні. Для публічного HTTPS
обов’язково true. Nginx обмежує POST входу через map/limit_req у http context.

Альтернатива без домену — прямий HTTPS на IP (docs/ip-https.md). Початковий
nginx-ip-bootstrap.conf відкриває тільки ACME-challenge, не форму входу. Після
видачі сертифіката nginx-ip-https.conf проксіює панель лише через TLS; потрібен
SESSION_COOKIE_SECURE=true. IP-сертифікат shortlived потребує поновлення:
serverwatch-certbot.timer використовує окремий Certbot 5.4+ та reload Nginx.
Публічно відкриваються лише 80/443 і раніше дозволений SSH; Gunicorn та MySQL
залишаються непублічними. Приватний TLS-ключ читає root/Nginx, не API застосунку.

## Ключі та коди

SSH-ключі й TOTP-секрети шифруються Fernet до запису в MySQL. ENCRYPTION_KEY
перебуває лише в /etc/serverwatch/serverwatch.env, окремо від резервної копії БД.
Власник файлу root, група serverwatch, режим 0640. У `.env.example` секретів немає.

setup_environment.py генерує секрети без виведення, відмовляється від перезапису.
Окремі migration.env та одноразовий bootstrap.sql мають root:root 0600; після
перевірки MySQL bootstrap.sql видаляється. manage.py upgrade читає DDL-credential
і знижує uid/gid до serverwatch перед запуском Flask. Інші процеси використовують
тільки runtime-роль. Ці файли читаються як dotenv/systemd EnvironmentFile, не shell.
Не запускайте setup_environment.py під час відновлення — потрібні первинні секрети.
restore_database_users.py створює ролі зі збережених URI лише на новому сервері,
не змінює паролі наявних ролей. Root запускає тільки цільові provisioning/backup
операції; вебпанель, бот і моніторинг root-привілеїв не мають.
Для попередніх підключень приватний SSH-ключ приймається лише на запис: не повертається API, шаблонами
або формою редагування. Некоректні поля не відображають введений ключ повторно.
Ключ SSH передається Paramiko в пам’яті; тимчасових файлів із ключами немає.

15-значний код генерується secrets, включно з можливими початковими нулями.
Зберігається лише HMAC-SHA256 із SECRET_KEY та строком 24 години; унікальність
підкріплена індексом БД. Споживання — умовне атомарне оновлення й транзакція.
Повторний випуск анулює попередній код. Зміна SECRET_KEY анулює сесії та коди.
Наявність коду не дає адміністративних прав: потрібен TELEGRAM_ADMIN_ID.

Telegram username використовується тільки для згадки @Yureweo. Авторизація груп,
підтвердження аварії та запит SWAP перевіряють числовий ID на backend і належність
аварії групі. Інші учасники можуть запитувати звіти. Коди бажано надсилати `/bind`,
оскільки privacy mode Telegram може приховувати звичайні повідомлення від бота.
Бот намагається видалити повідомлення з успішно використаним кодом.

## SSH та віддалене виконання

Політика RejectPolicy: автоматичне прийняття невідомих ключів хоста заборонено.
Звірте fingerprint через незалежний канал перед додаванням до known_hosts.
Зміна ключа хоста викликає помилку, не автоматичне перепідключення.
Збір виконує фіксований Python-скрипт стандартної бібліотеки; потрібен python3 на Linux.
Список systemd-сервісів обмежений 20 і проходить allowlist-перевірку назв.
Локальні subprocess викликаються списками аргументів без shell=True. Віддалений SSH
запускає фіксовану команду зі статичним heredoc; аргументи екрануються shlex.
Підключення й виконання мають обмежений час, вихід — обмежений розмір.
Сирий journal MESSAGE не зберігається й не передається в Telegram: лише назва
systemd unit, час і класифікована подія. Назви серверів і події HTML-екрануються.

## Автоматичні дії

Глобальний перемикач за замовчуванням вимкнено. На VPS кожна дія має окремий
перемикач. Worker перевіряє актуальні метрики, а lease БД виключає одночасні
операції з обслуговування VPS. Перервані завдання фіксуються після завершення lease.

Постійний SWAP використовує окремий root-owned helper без аргументів. Він працює
з фіксованими шляхами, flock, O_EXCL/O_NOFOLLOW, правами 0600 і перевіркою
файлової системи, вільного місця та /proc/swaps. Helper виділяє один файл 2 GiB
і вмикає systemd swap unit. Наявний SWAP залишається активним. Попередній helper
на старих VPS підтримує ручний тимчасовий SWAP 1 GiB.

Автоматичне відновлення CPU потребує послідовних вимірювань і доставленого
попередження. Зміна boot ID підтверджує перезавантаження. Автоматична спроба
обмежена однією на 24 години для VPS. Перезапуски сервісів обмежені інвентарем
вебпанелі та точними правилами sudoers на хості.

## Вебтермінал

SSH PTY використовує окремий зашифрований ключ непривілейованого акаунта.
WebSocket перевіряє Origin, свіжий вхід та власника дозволу для конкретного VPS.
Сеанс має ліміти тривалості та неактивності. Журнал зберігає відкриття й
завершення сеансу. Потік, команди та ключі не записуються до журналу.

## Експлуатація

Не запускайте застосунок від root. MySQL слухає тільки loopback, runtime-користувач
має SELECT/INSERT/UPDATE/DELETE тільки на власну БД; міграції виконує окремий користувач.
Systemd задає NoNewPrivileges, PrivateTmp, ProtectSystem, ProtectHome.
SSH sudo працює на віддаленій машині; центральний процес підвищення привілеїв не має.
Логи — journald з лімітом розміру. Обгортки worker/bot логують клас помилки без
тексту винятків і токенів. Не вмикайте Flask debug, SQL echo чи Paramiko debug.
Права читання `.env`, резервних копій і процесу застосунку рівнозначні доступу до секретів.

Черга Telegram забезпечує доставку з повторними спробами, семантика at-least-once:
після збою між відправкою та commit можливий повтор повідомлення. Exactly-once
Telegram API не гарантує. Lease БД захищає моніторинг та чергу; запускайте по одному
monitor і bot systemd-сервісу. Єдиний cleanup працює в monitor, не в Gunicorn.

Unit monitor додатково утримує flock, щоб повторний запуск того самого unit
не створював інший scheduler. Прямий запуск python в обхід unit не дозволений
процедурою експлуатації. Backup timer викликає root-owned скрипт з pipefail,
flock, приватним тимчасовим файлом і перевіркою gzip. Його дампи зберігаються в каталозі
root 0700. Дампи керованих VPS зберігаються окремо в приватному `instance/vps-backups`
з перевірками ZIP і SHA-256. Секрети архівуються окремо та шифруються перед перенесенням назовні.

AI вимкнений за замовчуванням. Дозволено тільки локальний Ollama endpoint;
передаються чотири відсоткові показники без IP, імен, ключів і журналів. Відповідь
обмежена, екранується та використовується лише як текст. Жодних інструментів для AI немає.
Не запускайте локальну LLM на центральному сервері 1 GB RAM; стандартні звіти не
потребують AI. Платних API та обов’язкових зовнішніх AI-залежностей немає.

Перед зміною SSH, UFW або sudoers перевірте альтернативну SSH-сесію, консоль
провайдера й можливість відновлення. Ротація Fernet вимагає окремої процедури
перешифрування; не змінюйте ENCRYPTION_KEY без міграції чинних шифротекстів.

## Майстер підключення клієнтів

Нові сервери отримують окремі Ed25519, згенеровані cryptography без тимчасових
приватних файлів. Приватна частина шифрується Fernet, публічна зберігається окремо
й передається клієнту лише в установчому скрипті. API повертає тільки стан, не ключі.
Видача та повторний випуск скрипта вимагають адміністративної сесії з TOTP і CSRF.

Токен скрипта — secrets.token_urlsafe(32), HMAC-SHA256 із окремим namespace у БД,
строк одна година. Він прив’язаний до ID сервера; completed/failed споживають його
під блокуванням рядка. Started дозволяє повтор повідомлення до завершення, але
не подовжує строк. Випуск нового скрипта анулює старий токен і попередній bind-код.
Скрипт секретний до споживання: не комітьте й видаліть завантажений файл після роботи.
Він не повертається повторно на GET, Bearer не передається в URL і не логується.

Callback приймається тільки через HTTPS, TLS на клієнті перевіряється стандартним
CA trust store. PUBLIC_BASE_URL задається в довіреному environment, а не береться
із Host запиту. П’ять невдалих callback за IP блокують спроби на 15 хвилин.
Endpoint звільнений від cookie-CSRF тільки тому, що використовує одноразовий Bearer.
Host key закріплюється через цей токен, перевіряється Paramiko RejectPolicy і не
замінюється автоматично. Секретність скрипта критична для першого закріплення.
READY виставляє worker лише після реального SSH-збору метрик. Telegram-код має
окремий строк 24 години; ACTIVE настає після авторизації головним адміністратором.

Клієнтський root потрібен лише для інсталятора. Фоновий monitor непривілейований,
з окремим home і читанням systemd-journal. Ключ має restrict та forced command:
без shell, forwarding, PTY, user rc або довільного запуску команд. Root-owned
Python dispatcher запускається з -I та приймає фіксовані операції збору, SWAP,
перезапуску, бекапу й reboot. Список сервісів і час перевіряються до виклику
збирача. Кожен привілейований виклик потребує точного правила sudoers на хості.
Файли authorized_keys доповнюються без перезапису сторонніх рядків; символьні
посилання й небезпечні власники відхиляються. Глобальний sshd_config не змінюється.

## Перевірки

`python -m pytest -q` перевіряє основні захисні механізми з mock SSH і SQLite.
Це не замінює acceptance-перевірку на цільовому MySQL, Linux, Nginx і Telegram.
Не використовуйте реальні приватні ключі чи production-токени в тестах.
